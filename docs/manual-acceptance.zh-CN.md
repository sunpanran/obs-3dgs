# 交付前人工验收

自动化结果与复现命令见 [测试说明](testing.zh-CN.md)。本表保留需要实际 OBS 窗口或指定硬件的检查，未勾选项不代表已经通过。

## Windows / macOS 前端

下面七项可先在 Windows 完成，结果按平台分别记录。收到 Windows 通过结果后，可以发布 Beta，并在 README 和发布说明中保留“macOS 尚未实机验证”的明确说明。Apple Silicon 的检查仍保留为待验证；RTX 4060 属于后续 Stable 验收。

### 开始前

1. 使用 `0.1.0-beta.1` Windows x64 包，在 OBS 中通过“场景集合 → 新建”建立专用验收集合。
2. 将公开示例 `knock-community-hall.sog` **复制一份**到自己的测试目录，后面的移动文件检查只移动这份副本。
3. 新建名为 `3DGS-A` 的来源，加载样例副本；在来源属性中点击“打开实时控制面板”，再点“确定”关闭属性窗口。Dock 的“来源”选择自动跟随或明确选择当前测试来源。
4. 在“相机”分类设置“全画幅等效焦段”为 35 mm，在 Dock **向下滚动到最底部的“镜头预设”**，点击“保存当前”，命名为 `镜头 A`；再用 85 mm 保存 `镜头 B`。应用 `镜头 A`，作为初始画面。
5. 记录 Windows、OBS、插件版本、GPU 和输出分辨率。先关闭“直播防误触”，第 4、5 项再测试锁定状态。

### 七项检查

- [ ] **1. 副本独立。** 在 `3DGS-A` 属性的“相机”分类勾选“显示高级相机参数”，确定关闭。通过来源列表右键“复制 → 粘贴（副本）”建立 `3DGS-B`。副本打开时应继承分类和高级相机展开状态；将副本焦段改为 50 mm、保存一个新预设、切到“显示”分类。重开原来源，原来的焦段、预设列表、分类和高级相机状态应保持原样。此项检查实际菜单操作，底层原生复制与私有状态隔离已有 100 次自动验证。
- [ ] **2. 取消恢复。** 在 `3DGS-A` 记录当前焦段、曝光和位置 X；修改这三项，最后浏览“显示”分类，然后点击属性窗口“取消”。画面和三个参数应恢复，重开属性时仍停留在最后浏览的分类。再修改一次并点窗口关闭按钮；如出现保存确认，选择放弃修改后也应恢复。对应 libobs 取消调用路径已自动验证，此处验证窗口操作。
- [ ] **3. 属性、Dock 和交互同步。** 将 `3DGS-A` 属性中的焦段改为 85 mm 并确定，Dock 应显示 85；在 Dock 输入 35 并按 Enter，画布和重开的属性页应同步。输入数字时中途停顿 1–2 秒，未提交内容不应被刷新覆盖。点击“鼠标调整视角”，拖动取景后关闭，画面和相机参数不应跳回。切换到 `3DGS-B` 再切回，数值应分别对应各自来源。
- [ ] **4. 直播防误触。** 对 `3DGS-A` 开启“直播防误触”。场景文件、场景变换、相机、显示和质量的修改控件应被锁定，鼠标交互不能改变相机；仍可浏览设置分类，并在 Dock 中应用已保存的 `镜头 A`、`镜头 B`。解锁后应恢复编辑。
- [ ] **5. 实际热键。** 在“OBS 设置 → 热键”中，为 `3DGS-A` 的“3DGS：镜头预设 1”和“3DGS：镜头预设 2”分别绑定未占用的组合键。返回 OBS 主窗口，实际按键应切换两个镜头，画面与 Dock 选择同步；开启“直播防误触”后仍可切换。测试后可移除这些临时绑定。
- [ ] **6. 缺失文件窗口。** 正常退出 OBS，将测试目录中的样例副本移动到另一个目录，再启动 OBS。在 OBS“缺失文件”窗口中定位新文件；使用该样例的来源应恢复画面，镜头预设仍保留。再次关闭并重开 OBS，路径应已保存，不再提示该文件缺失。
- [ ] **7. 摄像头、透明和滤镜合成。** 在测试场景中添加底层颜色来源，将 3DGS 放在颜色来源上方，摄像头放在最上方。将 3DGS 的“背景”设为“透明”，临时将“场景透明度”设为 0.5（50%），应能看到底层颜色参与合成，摄像头仍在前景。给 3DGS 加“色彩校正”，给摄像头加“裁剪/填充”等实际使用的滤镜，开关滤镜后画面应正常，无黑屏、错误遮挡或闪烁；结束时恢复场景透明度。没有摄像头或某项无法操作时，记录“未测”，不计作通过。

## Apple Silicon 门槛

macOS Universal 构建通过只证明编译、测试与打包；以下项目须在真实 Mac 的 OBS 中完成。

- [ ] 安装 Universal 包并确认 OBS 日志成功加载 `obs-3dgs`。
- [ ] Apple M1：1920×1080、30 FPS、75% 内部比例、1M LOD、SH2。若将目标 FPS 从平衡预设的 60 改为 30，界面会显示“自定义”，其余数值维持平衡档即可。
- [ ] 使用 `Knock Community Hall` 和固定相机，记录平均 ≥29 FPS、逐帧 P95 ≤36 ms、渲染延迟丢帧 <0.5%。保留原始帧时间、截图、设备信息与相机设置。
- [ ] 静止观察时没有持续重绘和排序；重复加载/卸载后内存不持续增长。

在已设好上述 30 FPS 参数的专用 OBS 简单输出配置中，选择可用的 macOS 录制编码器。设置本机 WebSocket 密码后可运行以下命令；脚本按实际 GPU、数值画质、逐帧数据与录制文件检查 M1 门槛，不会把 M1 Pro/Max 或软件渲染器算作基础 M1。

```text
npm run test:obs:renderer -- --duration-seconds 60 --record true --gate apple-m1 --pose docs/benchmarks/data/knock-community-hall-close-camera.json
```

RTX 4060 8 GB 同标准为 Stable 门槛；M2+ 1080p60 为目标，不阻塞首个 Beta。RAD 已有单文件最小样例实测；大场景和外部多文件分块不属于该样例覆盖。
