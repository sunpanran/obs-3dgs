# 群组来源与 Dock 布局回归 — 2026-09-04

[English](2026-09-04-dock-groups-layout.md)

Windows 用户确认 fix1 的预设热键和缺失文件恢复通过后，报告群组内来源无法自动跟随，以及实时控制面板过于拥挤。

自动选择此前只枚举当前场景的顶层项目。修复后递归枚举群组：优先跟随明确选中的 3DGS 来源；没有明确来源时，选中的群组仅含一个独立 3DGS 来源才自动跟随。群组内存在多个不同来源时显示选择提示；同一来源的多个引用不视为不同来源。

Dock 使用 OBS 原生样式，分为“相机 / 场景 / 预设”三个页签。来源选择占满一行，画质和语言分列，直播防误触独立成行。参数名称与数值位于上方、滑杆占满下方一行；常用焦段使用三列两行，按钮和分区增加间距。预设可以直接通过页签访问。

验证：

- `cmake --build --preset windows-ci-x64 --parallel` 严格编译与 Web 类型检查、构建通过。
- 四组 CTest 通过。新增的 `obs-3dgs-source-selection-tests` 使用真实 libobs 来源和群组结构，覆盖 12 项选择检查，包括群组内来源、嵌套群组、单一来源群组、多个来源提示、明确选择优先级与共享来源引用。
- Qt 回归验证 300 像素宽度下数值框位于滑杆上方、滑杆保持整行宽度、输入框不超出边界；既有输入焦点、延迟编辑隔离、预设同步和面板显示检查保持通过。
- 独立 Windows OBS 中已创建嵌套群组和来源并报告场景就绪。实际窗口的视觉验收由用户手动完成；没有记录为已经通过。

复测重点见[人工验收清单](../manual-acceptance.zh-CN.md)。回归使用独立测试目录中的原始小型 PLY 副本。
